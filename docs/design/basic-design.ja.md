## 1. システム概要

### 1.1 目的

本好きの個人が、自分の蔵書と読書の記録を1か所で管理できるようにする。書籍の基本情報に加え、読書の進み具合、何度読んだか、読みながら得た感想や学び・抜粋を残し、あとから検索して見返せることを目的とする。

### 1.2 対象利用者

- 紙・電子を問わず本を読む個人（専門知識は不要）
- 複数の言語圏の利用者（7言語の表示に対応）

### 1.3 動作環境

| 区分 | 内容 |
|---|---|
| 対応OS（現行） | Windows 10/11、macOS、Linux（いずれも64bit） |
| 対応OS（将来） | iPhone / iPad、Android スマートフォン / タブレット |
| ネットワーク | 原則不要。ISBN からの書籍情報取得と、Google ドライブとの同期（ログインした場合だけ）で使う |
| データの保存先 | 端末内（SQLite データベース1ファイル）。同期を使う場合は、利用者の Google ドライブのアプリ専用領域にも同じ内容を置く（[6.7](#67-クラウドに置くデータ)） |

### 1.4 用語

| 用語 | 意味 |
|---|---|
| 書影 | 本の表紙の画像 |
| ノート | 書籍ごとに付ける自由記述のメモ。分類とページを任意で付けられる |
| 読了日 | その本を読み終えた日。再読に備えて1冊に複数記録できる |
| 進捗 | 読書中の本をどこまで読んだかの割合（0〜100%） |
| 削除済みの印 | 削除したデータの行を残し、削除日時を記録したもの。同期で「削除」を他の端末へ伝えるために使う |
| 同期 | 同じ Google アカウントでログインした複数のパソコンで、書籍とノートを同じ内容にそろえること。Google ドライブを中継に使う |
| アプリ専用領域 | Google ドライブの中にある、そのアプリ専用の非公開の領域（appDataFolder）。利用者のほかのファイルとは分けて置かれる |
| 同期データ | 同期のために Google ドライブに置く、書籍とノートの内容。書影は画像ごとに別のファイルにする |
| 初めての同期 | そのパソコンでまだ一度も同期していない状態での同期。パソコンとクラウドの両方にデータがあれば、合わせ方を利用者が選ぶ |

## 2. 機能一覧

| ID | 機能 | 概要 |
|---|---|---|
| F-01 | 言語選択 | 初回起動時に表示言語を選ぶ。設定画面でいつでも変更できる |
| F-02 | 書籍の登録・編集・削除 | 書籍名（必須）・著者・翻訳者・監修・出版社・ISBN・版数を管理する |
| F-03 | ISBN からの取得 | ISBN を基に外部サービスから書誌情報を取得し、反映する項目を選ぶ |
| F-04 | 書影の設定 | 端末内の画像を手動で設定する。大きな画像は自動で縮小する（設定で無効化可） |
| F-05 | 読書ステータス | 未設定（初期値）・未読・読書中・読了。読書中は進捗%を任意で入力 |
| F-06 | 読了日の記録 | 1冊に複数の読了日を記録する。読了にしたとき今日の日付の追加を提案する |
| F-07 | ノート | 任意の数のノートを追加・並べ替え・削除する。ノートごとにお気に入りの印（★）を付けられる |
| F-08 | タグ | 1冊に複数のタグを付ける。タグの名前変更・削除を一括で行う |
| F-09 | 一覧表示 | 書籍名の一覧と書影の一覧を切り替える。登録日順・書籍名順で並べ替える |
| F-10 | 検索 | 書籍情報とノート本文を検索し、各種条件で絞り込む |
| F-11 | エクスポート | テキスト（書影を含めることも可）・JSON＋画像（ZIP）・SQLite の3形式で書き出す |
| F-12 | インポート | ZIP・SQLite から「すべて置き換え」または「追加」で復元する |
| F-13 | 設定 | 表示言語・配色テーマ・明るさ・書影の自動縮小・同期・すべてのデータの削除・アプリ情報 |
| F-14 | ビューアモード | 登録済みの書籍を見る専用で表示する。入力済みの項目だけを出し、編集用の操作は出さない。編集モードと切り替えられる |
| F-15 | 同期 | Google アカウントでログインし、Google ドライブのアプリ専用領域を介して、複数のパソコンの書籍・ノート・読了日・タグ・書影をそろえる。起動時・変更後・終了前に自動で同期し、「今すぐ同期」でも実行できる。ログインしなければ同期は行わない |

## 4. システム構成

### 4.1 全体構成

アプリは端末内で完結する。外部との通信は、ISBN 取得のときの書誌情報サービス（5か所）と、同期を使う場合の Google（ログインと Google ドライブ）だけである。

```mermaid
flowchart TB
    subgraph device["利用者の端末"]
        subgraph colophon["Colophon（Flutter アプリ）"]
            ui["画面（UI）"]
            state["状態管理<br/>設定・書籍一覧・同期の状態"]
            service["業務処理<br/>検索・書影・ISBN・入出力・ログイン"]
            sync["同期<br/>統合・Google ドライブとの送受信"]
            repo["データアクセス"]
        end
        db[("SQLite<br/>colophon.db")]
        prefs[("端末設定<br/>表示言語など")]
        files[/"端末のファイル<br/>画像・エクスポートファイル・<br/>同期の記録・同期前のバックアップ"/]
        secure[("OS の安全な保管場所<br/>Google のログイン情報")]
        browser["ブラウザ"]
    end
    ndl["国立国会図書館サーチ API"]
    others["Open Library・米国議会図書館・<br/>フランス国立図書館・ドイツ国立図書館の API"]
    google["Google<br/>ログイン（OAuth 2.0）・<br/>Google ドライブ API"]

    ui --> state --> repo
    ui --> service
    service --> repo
    state --> sync --> repo
    repo --> db
    state --> prefs
    service <--> files
    sync <--> files
    service <--> secure
    ui -- "ログイン時に開く" --> browser
    browser -- "HTTPS" --> google
    service -- "HTTPS（ISBN取得時のみ）" --> ndl
    service -- "HTTPS（ISBN取得時のみ）" --> others
    service -- "HTTPS（ログイン・ログアウト時）" --> google
    sync -- "HTTPS（ログイン中のみ）" --> google
```

### 4.2 層の役割

| 層 | 役割 | 主なフォルダ |
|---|---|---|
| 画面（UI） | 入力の受付と表示。業務ルールは持たない | `lib/ui/` |
| 状態管理 | 画面が共有する状態（設定・書籍一覧・同期のログイン状態と実行状況）を保持し、変更を画面へ通知する。自動同期の時機を決める | `lib/state/` |
| 業務処理 | 検索・書影の縮小・ISBN の検証と取得・エクスポート／インポート・Google へのログイン・記録時刻（サーバー時刻で補正した現在時刻） | `lib/services/` |
| 同期 | 同期データの形式・統合の規則・Google ドライブとの送受信・同期の記録・初めての同期の前のバックアップ | `lib/sync/` |
| データアクセス | SQLite の読み書きとスキーマの移行。同期データの取り出しと書き込み | `lib/data/` |
| モデル | 書籍・ノートなどのデータの型 | `lib/models/` |

### 4.3 採用技術

| 用途 | 技術 |
|---|---|
| アプリ基盤 | Flutter（Dart）。1つのコードで各OS版を作る |
| データベース | SQLite（`sqlite3` パッケージ） |
| 多言語 | Flutter 標準の多言語機能（ARB ファイル） |
| 端末設定の保存 | `shared_preferences` |
| ファイル選択・保存 | `file_picker` |
| 画像処理 | `image`（縮小・形式変換） |
| ZIP | `archive` |
| Google ドライブ | `googleapis`（Drive API v3） |
| Google へのログイン | `googleapis_auth`（認可コードの交換・トークンの更新） |
| ログイン情報の保存 | `flutter_secure_storage`（OS の安全な保管場所） |
| ブラウザを開く | `url_launcher` |
| ハッシュ | `crypto`（書影の SHA-256、ログインの PKCE） |

### 5.3 各画面の概要

#### SC-01 言語選択

| 項目・操作 | 内容 |
|---|---|
| 言語の一覧 | English / 日本語 / 简体中文 / Français / Español / Deutsch / 한국어。各言語自身の表記で表示する |
| 初期選択 | 端末の言語が対応言語ならそれ、なければ English |
| 言語を選ぶ | 画面の表示がその場で選んだ言語に切り替わる（確定はしない） |
| 続ける | 選んだ言語を保存し、書籍一覧へ進む |

#### SC-02 書籍一覧

| 項目・操作 | 内容 |
|---|---|
| 書籍名の一覧 | 縮小書影・書籍名・著者・タグ・ステータスを1行ずつ表示 |
| 書影の一覧 | 書影を格子状に並べる。書影がない本は書籍名入りの仮表紙を表示 |
| ステータス表示 | アイコン＋文字で表示（色だけに頼らない）。読書中で進捗が入力されているときだけ「読書中 40%」のように%を添える |
| 読了回数 | 2回以上読了した本に「2回読了」などを表示 |
| 表示切替 | 書籍名の一覧 ⇔ 書影の一覧（選択は端末に保存） |
| 並び替え | 登録日の新しい順／書籍名順（選択は端末に保存） |
| メニュー | タグの管理・エクスポート・インポート・設定 |
| ＋ボタン | 書籍の新規登録（SC-03） |

#### SC-03 書籍の表示・登録・編集

登録済みの書籍はビューアモード（見る専用）で開き、上部の「表示／編集」の切り替えで編集モードにする。新規登録は編集モードだけで、切り替えは出さない。

**ビューアモード**

| 項目 | 表示 |
|---|---|
| 書影 | 登録されていれば左に表示 |
| 書籍名・書誌項目 | 書籍名と、入力済みの項目（著者・翻訳者・監修・出版社・ISBN・版数）だけを「項目名 値」で表示。未入力の項目は項目名ごと出さない |
| ステータス | アイコン＋文字（読書中で進捗が入力されていれば%も） |
| 読了日・タグ | あるときだけ見出しごと表示 |
| ノート | あるときだけ表示。各ノートは、分類とページ（入力されていれば）の小さな見出し＋本文。お気に入りのノートには★を出すが、押しても切り替わらない |
| 登録日・更新日 | 最下部に小さく表示 |
| 出さないもの | 入力欄、保存・削除ボタン、ノートの並べ替え・削除、☆ボタン |

文字は選択してコピーできる。日付は年を含めて表示する（例: 2025年3月1日）。

**編集モード**


| 区分 | 項目・操作 | 内容 |
|---|---|---|
| 書影 | 画像を選択／画像を削除 | 端末の画像を選ぶ。条件により自動縮小（[8.3](#83-書影の登録)） |
| 書誌情報 | 書籍名 | 必須。未入力では保存できない |
| | 著者・翻訳者・監修・出版社・版数 | 任意の自由入力 |
| | ISBN | 任意。正しくない番号のときは警告を出すが、保存は止めない |
| | ISBN から取得 | 正しい ISBN のときだけ実行できる（[8.2](#82-isbn-からの書籍情報取得)） |
| 読書 | ステータス | 未設定・未読・読書中・読了 |
| | 読んだ割合（%） | ステータスが読書中のときだけ表示。0〜100 の整数、任意 |
| | 読了日 | 追加・変更・削除。読了に変えたとき今日の日付の追加を提案 |
| タグ | タグ入力 | 既存タグを候補として表示。Enter で追加 |
| ノート | 分類・ページ・本文 | 分類は任意（感想・学び・メモ・抜粋・その他）。ページは1以上の整数、任意 |
| | お気に入り（☆／★） | 押すたびに登録・解除。保存ボタンで確定 |
| | 追加・上下移動・削除 | 本文があるノートの削除は確認する |
| 操作 | 保存（Ctrl+S／⌘S） | 入力チェックの後に保存する。登録済みの書籍はビューアモードに戻り、新規登録は一覧へ戻る |
| | 書籍を削除 | 確認のうえ削除（編集時のみ） |
| | 戻る・ウィンドウを閉じる | 未保存の変更があれば破棄の確認を出す |

**同期との関係**

| 場面 | 動作 |
|---|---|
| 開いている書籍が同期で変わった | 未保存の変更がなければ、最新の内容で表示し直す（ダイアログを開いている間は除く）。未保存の変更があれば入力を優先し、保存すればそちらが新しい内容になる |
| 開いている書籍がほかのパソコンで削除された | 「この書籍は、ほかのパソコンで削除されました。」と知らせて画面を閉じる。保存や「破棄して表示」のときに気づいた場合も同じで、保存はしない（保存すると、すべてのパソコンで復活してしまうため） |
| 編集中に同期で届いたノート | 保存しても消さない（削除済みにするのは、この画面で削除したノートだけ） |

#### SC-04 ISBN 取得結果

取得できた項目（書籍名・著者・翻訳者・監修・出版社・版数）をチェックボックス付きで表示する。初期状態では、編集中の書籍で**まだ空欄の項目だけ**にチェックを付ける。入力済みの項目には現在の値を併記する。取得元の名前（出典）と、「翻訳者・監修の判別が不完全な場合がある」旨を表示する。

#### SC-05 検索

| 項目 | 内容 |
|---|---|
| キーワード | 空白区切りで複数語（すべてを含むものに一致）。入力の0.2秒後に自動で検索 |
| 検索対象 | 書籍名・著者・翻訳者・監修・出版社・ISBN・ノート本文（初期値はすべて） |
| ステータス | 選んだステータスのいずれか |
| ノートの分類 | 選んだ分類（「分類なし」を含む）のノートに絞る |
| お気に入り | お気に入りのノートだけに絞る（分類と両方選ぶと両方を満たすもの） |
| タグ | 選んだタグを**すべて**持つ書籍 |
| 読了日の期間 | 開始日〜終了日（両端を含む。片方だけでも可） |
| 結果 | 書籍ごとに表示し、一致したノートを本文の抜粋付きで並べる。選ぶと SC-03 へ。ノートの☆を押すと、その場でお気に入りを切り替えて保存する |

#### SC-06 タグ管理

タグの一覧を付いている冊数とともに表示する。名前の変更（ほかのタグと同じ名前は不可）と削除（全書籍から外れる）ができる。

#### SC-07 設定

| 項目 | 内容 |
|---|---|
| 表示言語 | 7言語から選ぶ。即時に反映 |
| 配色テーマ | 6種類から見本を見て選ぶ。即時に反映（[5.4](#54-配色テーマ)） |
| 明るさ | OSに合わせる（初期値）／明るい／暗い |
| 書影の自動縮小 | オン（初期値）／オフ |
| 同期 | Google ドライブとの同期のログイン状態・最終同期日時・操作（下表） |
| すべてのデータを削除 | 書籍・ノート・タグ・読了日・設定をすべて削除し、言語選択画面から始まる最初の状態に戻す。①案内（「先にエクスポート」も選べる）②「元に戻せないことを理解しました」にチェックしないと押せない最終確認、の二段階で確認する。ログイン中は、最終確認で削除する範囲（このパソコンだけ／Google ドライブとすべてのパソコン）も選ぶ（[8.10](#810-すべてのデータの削除と同期)） |
| このアプリについて | バージョン、書籍情報の取得元、オープンソースライセンス |

**同期欄**

| 状態 | 表示・操作 |
|---|---|
| 使えない | 「このビルドでは同期を使えません」と表示し、操作は出さない（Google のクライアント設定を含めずにビルドしたアプリ） |
| 読み込み中 | 起動直後、保存したログイン情報を読む間は進行中の表示 |
| ログアウト中 | 同期の説明と「ログイン」ボタン（SC-10） |
| ログイン中 | 「ログイン中: メールアドレス」（取れなければ「ログイン中」）と「ログアウト」ボタン。ログアウトは確認してから行い、このパソコンと Google ドライブのデータはどちらも削除しない。同期中は押せない |
| | 最終同期日時（未同期なら「まだ同期していません」、同期中は「同期中…」と進行中の表示）と「今すぐ同期」ボタン。同期が終わると「同期しました。」、失敗すると理由を下部に表示する |
| | 前回の同期が失敗していれば、その理由を赤字で表示する（[8.7](#87-同期)）。失敗がなく、初めての同期の合わせ方を選ぶ必要があれば「「今すぐ同期」を押してください」、クラウドに読めない記録があれば送信を見合わせた旨を表示する |

#### SC-10 Google ログイン

同期欄の「ログイン」を押すと、既定のブラウザで Google のログイン画面を開き、このダイアログを出す。

| 項目・操作 | 内容 |
|---|---|
| 案内 | ブラウザで Google アカウントを選び、Colophon へのアクセスを許可するよう案内する。進行中の表示を出す |
| リンクをコピー | ログイン画面の URL をクリップボードへコピーする（ブラウザが開かないときや、別のブラウザを使いたいときに貼り付ける） |
| キャンセル | ログインを中止する。メッセージは出さない |
| 許可した | ブラウザに「Colophon にログインしました。このタブを閉じて、アプリに戻ってください。」を表示する。アプリは「ログインしました。」を出してダイアログを閉じ、すぐに同期する（必要なら SC-11） |
| 許可しなかった／失敗した | 「ログインが取り消されました。」／「ログインできませんでした。ネットワークの接続を確認して…」を表示し、ログアウト中に戻る |

#### SC-11 初めての同期

このパソコンでまだ一度も同期しておらず、このパソコンとクラウドの両方に書籍・ノートがあるときに出す。両方の冊数を示し、合わせ方を選んでもらう（[8.8](#88-初めての同期)）。同期の前に、このパソコンのデータのバックアップを自動で保存する旨も表示する。

| 選択肢 | 内容 |
|---|---|
| 統合する（おすすめ・初期選択） | 両方の書籍を残す。ISBN が同じ書籍は1冊にまとめる |
| Google ドライブの内容に置き換える | このパソコンだけにある書籍とノートは削除される |
| このパソコンの内容に置き換える | Google ドライブだけにある書籍とノートは、同期しているすべてのパソコンから削除される |

「同期する」で実行する。「キャンセル」では何もせず、選ぶまで自動同期も進めない（同期欄に案内を出す）。

#### SC-12 終了時の同期

ウィンドウを閉じるとき、まだ送っていない利用者の変更があれば「Google ドライブと同期しています…」「同期が終わったら終了します。」を表示し、同期が終わってから終了する。表示中はほかの操作をできない（同期中の編集が送られずに残るのを防ぐため）。「同期せずに終了」を押せば待たずに終了する（変更はこのパソコンに残り、次に起動したときに送る）。同期に時間がかかっても、実行中の同期を待つのに最大10秒、同期1回に最大10秒で打ち切って終了する。

#### SC-08 エクスポート／SC-09 インポート

[8.4](#84-エクスポート) と [8.5](#85-インポート) を参照。

### 5.4 配色テーマ

| テーマ | 特徴 |
|---|---|
| レザー（初期値） | 革装の本を思わせる茶系 |
| フォレスト | 深い緑系 |
| オーシャン | 紺・青系 |
| ローズ | 落ち着いた赤紫系 |
| モノクロ | 白・黒・グレーだけ（書影は登録した画像のまま表示） |
| ユニバーサル | 色覚の違いにかかわらず見分けやすい配色。カラーユニバーサルデザイン推奨配色セットの青・空色・オレンジを使い、赤と緑の区別に頼らない |

- どのテーマにも明るい版と暗い版があり、「明るさ」の設定で切り替える。
- ステータスは全テーマで「アイコン＋文字」でも区別できる（未設定＝空の丸、未読＝本、読書中＝しおり、読了＝チェック）。
- 全テーマ・明暗で、文字と背景のコントラスト比は WCAG 2.x の AA（4.5:1）以上とする。
- モノクロとユニバーサルは、P型・D型・T型の色覚でもステータスの色どうしが見分けられる（色差 ΔE 20 以上）ことを自動テストで確認する。

| 項目 | 必須 | 形式・制約 | 補足 |

| 書籍名 | ○ | 文字列（前後の空白を除いて1文字以上） | |

### 6.4 ノートの項目定義

| 項目 | 必須 | 形式・制約 |
|---|---|---|
| 分類 | | 感想・学び・メモ・抜粋・その他、または未選択 |
| ページ | | 1以上の整数 |
| お気に入り | ○ | あり／なし（初期値はなし） |
| 本文 | | 複数行の文字列 |
| 並び順 | ○ | 画面での並びの順 |

本文・分類・ページがすべて空のノートは保存しない。

### 6.5 コード値

画面の言語に依存しないよう、データベースとエクスポートファイルには次のコードを保存する。

| 区分 | コード | 表示（日本語） |
|---|---|---|
| ステータス | `unset` / `unread` / `reading` / `finished` | 未設定／未読／読書中／読了 |
| ノートの分類 | `impression` / `learning` / `memo` / `excerpt` / `other` / なし | 感想／学び／メモ／抜粋／その他／分類なし |

### 6.6 削除の扱い

書籍・ノートを削除しても行は残し、削除日時（`deleted_at`）を記録する。書影とノート本文は消去する。画面・検索・エクスポートには現れない。同期で、削除を他の端末へ伝えるための仕組みである（[8.7](#87-同期)）。設定画面の「すべてのデータを削除」だけは、削除済みの印も残さず物理的に消す。

### 6.7 クラウドに置くデータ

同期を使うと、利用者の Google ドライブのアプリ専用領域（appDataFolder）に次のファイルを置く。Colophon はアプリ専用領域だけを読み書きできる権限（`drive.appdata`）でログインするため、利用者のほかのファイルには触れない。

```mermaid
flowchart LR
    subgraph pcA["パソコンA"]
        a[(colophon.db)]
    end
    subgraph pcB["パソコンB"]
        b[(colophon.db)]
    end
    subgraph drive["利用者の Google ドライブ（アプリ専用領域）"]
        snap["colophon-sync.json<br/>書籍・ノート"]
        covers["cover-（SHA-256）<br/>書影1枚ごとに1ファイル"]
    end
    a <-- "同期（ログイン中のみ）" --> drive
    b <-- "同期（ログイン中のみ）" --> drive
```

| ファイル | 内容 |
|---|---|
| `colophon-sync.json` | 同期データ（通常は1つ。2台が同時に初めて送ると一時的に2つになり、次の同期で1つにまとめる）。全書籍（書誌項目・ステータス・進捗・読了日・タグ・ノートの並び順・書影の SHA-256 と MIME タイプ・登録日時・更新日時）と全ノート（分類・ページ・本文・お気に入り・登録日時・更新日時）。削除済みの書籍・ノートは、ID と日時だけを持つ |
| `cover-{SHA-256}` | 書影の画像。中身の SHA-256 を名前にするので、同じ画像は1つだけ置かれ、変わった画像だけを送ればよい。どの書籍からも使われなくなった書影は、そう分かってから7日以上たった後の同期で消す |

- 置かないもの: 設定（表示言語・配色テーマなど）、一覧用の縮小画像（受け取ったパソコンで作る）、削除した書籍の書誌項目と、削除したノートの本文。
- 形式の版（同期データ形式 v1）を持ち、新しい版のアプリが書いた同期データは、古いアプリでは読まず上書きもしない。

同期のためにパソコン側に置くもの:

| 置き場所 | 内容 |
|---|---|
| OS の安全な保管場所（Windows: 暗号化したファイル、macOS: キーチェーン、Linux: Secret Service） | Google のログイン情報（アクセストークン・更新用トークン）と、表示用のメールアドレス |
| 本棚（`colophon.db`）と同じフォルダの `sync-state.json` | 一度同期したか・最終同期日時・サーバー時刻との差 |
| 本棚と同じフォルダの `sync-backups/` | 初めての同期の前に取ったバックアップ（エクスポートと同じ ZIP 形式で、インポートで戻せる。新しい3つを残す） |

## 7. 状態遷移

### 7.1 読書ステータス

ステータスはどの値からどの値へも直接変更できる。代表的な流れと、変更時の振る舞いを示す。

```mermaid

    state "未読" as unread
    state "読書中" as reading
    state "読了" as finished

    unset --> unread
    unset --> reading
    unread --> reading: 読み始める
    reading --> finished: 読み終える
    finished --> reading: 再読する
    unset --> finished

    note right of reading
        進捗%を任意で入力できる。
        一覧に%を表示するのはこの状態のときだけ
    end note
    note right of finished
        この状態に変えたとき、
        今日の日付を読了日に追加するか確認する
    end note
```

### 7.2 書籍画面のモードと保存状態

```mermaid
stateDiagram-v2
    state "ビューアモード" as view
    state "編集（変更なし）" as clean
    state "編集（未保存の変更あり）" as dirty
    state "破棄の確認中" as confirm
    state "ビューアへの切り替えの確認中" as switchConfirm

    [*] --> view: 登録済みの書籍を開く
    [*] --> clean: 新規登録
    view --> clean: 「編集」に切り替え
    clean --> view: 「表示」に切り替え
    clean --> dirty: いずれかの項目を変更
    dirty --> switchConfirm: 「表示」に切り替え
    switchConfirm --> view: 保存して表示（入力チェックOK）
    switchConfirm --> view: 破棄して表示
    switchConfirm --> dirty: キャンセル
    dirty --> view: 保存（登録済み・入力チェックOK）
    clean --> view: 保存（登録済み）
    dirty --> [*]: 保存（新規登録・入力チェックOK）
    dirty --> dirty: 保存（入力チェックNG）
    view --> [*]: 戻る・閉じる
    clean --> [*]: 戻る・閉じる
    dirty --> confirm: 戻る・ウィンドウを閉じる
    confirm --> [*]: 破棄
    confirm --> dirty: キャンセル
```

ビューアモードには常に保存済みの内容を表示するため、未保存の変更があるまま「表示」に切り替えるときは、保存するか破棄するかを先に選んでもらう。

### 7.3 同期の状態

設定画面の同期欄（[5.3](#sc-07-設定)）は、次の状態に応じて表示を変える。

```mermaid
stateDiagram-v2
    state "使えない" as unavailable
    state "読み込み中" as loading
    state "ログアウト中" as signedOut
    state "ブラウザでのログイン待ち" as signingIn
    state "ログイン中" as signedIn
    state signedIn {
        state "待機" as idle
        state "同期中" as syncing
        [*] --> idle
        idle --> syncing: 自動同期・「今すぐ同期」
        syncing --> idle: 完了・失敗
    }

    [*] --> unavailable: クライアント設定なしのビルド
    [*] --> loading: クライアント設定ありのビルド
    loading --> signedIn: 保存したログイン情報がある
    loading --> signedOut: ログイン情報がない・読めない
    signedOut --> signingIn: 「ログイン」
    signingIn --> signedIn: 許可した
    signingIn --> signedOut: キャンセル・拒否・失敗
    signedIn --> signedOut: 「ログアウト」・すべてのデータの削除
```

- ログアウトすると、Google 側でもトークンを無効にし、保存したログイン情報と同期の記録（一度同期したか・最終同期日時）を消す。次にログインしたときは初めての同期として扱う（別のアカウントでログインしても、そちらのデータと正しく合わせるため）。
- ログアウトしても、このパソコンと Google ドライブのデータはどちらも削除しない。

### 8.2 ISBN からの書籍情報取得

ISBN の国・言語の番号（978-4 なら日本など）から問い合わせる順番を決め、見つかるまで順に問い合わせる（順番は [9.2](#92-取得元と問い合わせの順番)）。

```mermaid
sequenceDiagram
    actor U as 利用者
    participant E as 書籍の登録・編集画面
    participant S as ISBN 取得処理
    participant X as 取得元（順番に）
    participant D as ISBN 取得結果ダイアログ

    U->>E: ISBN から取得
    E->>E: ISBN のチェックディジットを確認
    alt 正しくない ISBN
        E-->>U: 「正しい ISBN を入力してください」
    else 正しい ISBN
        E->>S: 取得を依頼
        S->>S: ISBN の国番号から問い合わせる順番を決める
        loop 見つかるまで、順番に
            S->>X: ISBN で検索（国立国会図書館は15秒、ほかは10秒で打ち切り）
            X-->>S: 書誌情報／該当なし／通信エラー
        end
        alt 取得できた
            S-->>E: 取得結果
            E->>D: 現在の入力値と並べて表示（出典も表示）
            U->>D: 反映する項目を選ぶ
            D-->>E: 選ばれた項目
            E->>E: 入力欄に反映（保存はしない）
        else すべて正常に応答し、どこにもない
            S-->>E: なし
            E-->>U: 「見つかりませんでした」
        else 見つからず、通信エラーの取得元があった
            S-->>E: エラー
            E-->>U: 「取得できませんでした。接続を確認してください」
        end
    end
```

通信エラーの取得元に本があった可能性があるため、その場合は「見つからない」と言い切らない。
### 8.3 書影の登録

### 8.5 インポート

```mermaid
sequenceDiagram
    actor U as 利用者
    participant M as 書籍一覧
    participant I as インポート処理
    participant R as データアクセス

    U->>M: メニュー「インポート」
    M->>U: ファイルを選ぶ（.zip / .sqlite / .db）
    U->>M: ファイル
    M->>I: 読み込み（「処理中」を表示）
    I->>I: 先頭の内容で ZIP か SQLite かを判定
    alt Colophon のデータではない／新しい版のデータ
        I-->>M: エラー
        M-->>U: 理由を表示して終了
    else 読み込めた
        I-->>M: 書籍のリスト
        M->>U: 冊数を示し、方法を選ぶ（SC-09）
        opt 「すべて置き換える」で現在1冊以上ある
            M->>U: 「現在の N 冊は削除されます」と確認
        end
        M->>R: 反映（1つのトランザクション）
        R-->>M: 追加数・スキップ数
        M-->>U: 「追加 N 冊／スキップ M 冊」
    end
```

反映時の判定は次のとおり。全体を1つのトランザクションで行い、途中で失敗した場合は何も変更しない。

```mermaid
flowchart TD
    start([反映開始]) --> mode{方法}
    mode -- すべて置き換える --> delall[現在の全書籍に<br/>削除済みの印を付ける] --> loop
    mode -- 追加する --> loop
    loop[ファイルの書籍を1冊ずつ処理] --> dupId{同じ ID の書籍が<br/>登録されているか}
    dupId -- はい --> skip[スキップ]
    dupId -- いいえ --> isMerge{追加するか}
    isMerge -- いいえ<br/>（置き換え） --> add
    isMerge -- はい --> dupIsbn{正しい ISBN で<br/>同じ本が登録済みか<br/>※ISBN-10/13 は同一視}
    dupIsbn -- はい --> skip
    dupIsbn -- いいえ --> add[登録する<br/>削除済みの同じ ID があれば復活]
    skip --> next{次の書籍があるか}
    add --> next
    next -- はい --> loop
    next -- いいえ --> done([件数を報告])
```

- 置き換えのときは同じ ISBN でもスキップしない（同じ本を複数冊持つ利用者がいるため）。
- 正しくない ISBN（例: 「不明」）は同一判定に使わない。
- 取り込んだ書籍とノートの更新日時は、取り込んだ時刻にする。ファイルの日時のままだと、同期でクラウドの方が新しいと判定され、取り込んだ内容が元に戻されるため。
- 置き換えで付いた削除済みの印は、同期でほかのパソコンにも伝わる。

- 比較では大文字・小文字、全角・半角の違いを無視する。
- ISBN はハイフンの有無にかかわらず一致する。

### 8.7 同期

1回の同期では、クラウドの同期データとこのパソコンの内容を突き合わせて統合し、統合結果をクラウドへ送り、このパソコンへ書き込む。

```mermaid
flowchart TD
    start([同期を開始]) --> get[Google ドライブから同期データを取得]
    get --> first{初めての同期で、<br/>両方にデータがあるか}
    first -- はい --> choose[合わせ方を利用者が選ぶ<br/>SC-11] --> merge
    first -- いいえ --> merge
    merge[書籍・ノートごとに突き合わせ、<br/>更新日時の新しい方を採用して統合]
    merge --> dl[このパソコンにない書影を取得]
    dl --> isFirst{初めての同期か}
    isFirst -- はい --> backup[このパソコンのバックアップを保存] --> ul
    isFirst -- いいえ --> ul[クラウドにない書影を送る]
    ul --> need{クラウドへ<br/>送る必要があるか}
    need -- はい --> race{取得した後に、ほかのパソコンが<br/>同期データを書き換えたか}
    race -- はい（3回まで） --> get
    race -- いいえ --> upload[統合結果を送る]
    upload --> race2{送った直後に<br/>上書きされたか}
    race2 -- はい（3回まで） --> get
    race2 -- いいえ --> apply
    need -- いいえ --> apply[統合結果をこのパソコンへ書き込む<br/>同期中に編集した内容は残す]
    apply --> tidy[使われなくなった書影を片付ける]
    tidy --> done([最終同期日時を記録])
```

**統合の規則**

| 場面 | 結果 |
|---|---|
| 同じ書籍を2台で変えた | 更新日時が新しい方の書籍を丸ごと採用する（読了日・タグ・ノートの並び順も書籍の一部として扱う） |
| 同じノートを2台で変えた | ノートごとに、更新日時が新しい方を採用する（書籍とは別に判定する） |
| 更新日時が同じ | 削除を優先する。どちらも削除でなければクラウド側を採用する（どのパソコンでも同じ結果になるように） |
| 一方で削除し、他方で編集した | 後から行った方が勝つ。削除が後なら、その書籍のノートもすべて削除する。編集が後なら書籍は復活し、書籍と一緒に消えたノートも戻る（個別に削除したノートは戻らない） |
| 別々のパソコンで別々のノートを追加した | 両方残る。並び順に入っていないノートは、作成日時の順に後ろへ付ける |
| タグの表記だけが違う（「SF」と「sf」など） | 同じタグとみなし、違いとして扱わない |
| クラウドに読めない記録がある | 読める記録は取り込むが、このパソコンからは送らない（上書きで、その記録を消さないため）。その旨を表示する |
| クラウドの同期データが新しい版のアプリの形式・壊れている | 同期を中止し、上書きもしない |

- 記録する日時（登録・更新・削除）は、Google のサーバー時刻との差で補正する。パソコンの時計がずれていても、新しい方を正しく判定するため。
- 同期の途中で失敗・中断しても、このパソコンのデータは書き込み前のままである（書き込みは最後に1つのトランザクションで行う）。
- 送る前と送った直後にクラウドのファイルを確かめ、ほかのパソコンが書き換えていたら取得からやり直す（相手の変更を上書きしないため）。3回続けて重なったら「混み合っている」として失敗する。
- 書影は同期データより先に送る（ほかのパソコンが、まだ届いていない書影を参照しないように）。
- 失敗した場合は理由を同期欄に表示する。

| 失敗の理由 | 表示 | 自動の再試行 |
|---|---|---|
| 通信できない・Google 側の一時的な不調 | 接続できませんでした。… | する |
| ほかのパソコンの同期と何度も重なった | ほかのパソコンの同期と重なりました。… | する |
| クラウドにあるはずの書影がまだない | 表紙の画像がまだ届いていません。… | する |
| 想定外の失敗 | 同期できませんでした。 | する |
| ログインし直しが必要（許可の取り消し・期限切れなど） | Google ドライブを使う許可が無効になっています。… | しない |
| Google ドライブの容量不足 | Google ドライブの空き容量が足りません。 | しない |
| 新しい版のアプリが書いた同期データ | アプリを最新版に更新してください。 | しない |
| クラウドの同期データが壊れている | 同期データが壊れているため、同期を中止しました。 | しない |
| このパソコンへの保存（DB・バックアップ）の失敗 | このパソコンへの保存に失敗しました。… | しない |

### 8.8 初めての同期

そのパソコンでまだ一度も同期しておらず、クラウドとこのパソコンの両方に（削除済みでない）書籍・ノートがあるときだけ、合わせ方を選んでもらう（SC-11）。片方にしかデータがなければ選ばずに統合する。選んだ方法で同期する前に、このパソコンのデータを `sync-backups/` に保存する（Google ドライブに何か書く前に保存し、保存に失敗したら何も変えずに終える）。

| 方法 | このパソコンだけにある書籍 | クラウドだけにある書籍 | 両方にあって内容が違う書籍 |
|---|---|---|---|
| 統合する | 残して送る。ただし、クラウドだけにある書籍と正しい ISBN が同じなら1冊にまとめる | このパソコンへ取り込む | 更新日時が新しい方 |
| Google ドライブの内容に置き換える | 削除する（同期データはクラウドへ送らない） | このパソコンへ取り込む | クラウドの内容 |
| このパソコンの内容に置き換える | 残して送る | 削除済みにして送る（ほかのパソコンからも消える） | このパソコンの内容。更新日時を今にして送り、ほかのパソコンに残る版に負けないようにする |

ノートも書籍と同じ扱いをする。ISBN でまとめた書籍は、クラウド側の ID を使い（ほかのパソコンとそろえるため）、書誌項目は更新日時が新しい方、読了日とタグは両方を合わせたもの、ノートは両方とも残す。

### 8.9 自動同期

ログイン中は、次の時機に自動で同期する。

| きっかけ | 同期する時機 |
|---|---|
| 起動（ログイン情報が保存されている） | 3秒後 |
| 利用者の変更（書籍の保存・削除、お気に入りの切り替え、タグの名前変更・削除、インポートなど） | 最後の変更から30秒後。変更が続いても、最初の変更から5分たったら同期する |
| 同期中に変更があった | その同期が終わってから2秒後に、もう一度 |
| 一時的な失敗（[8.7](#87-同期) の表で「する」） | 1分・2分・5分・15分・30分後（以降は30分ごと）に再試行。成功すれば間隔を戻す |
| 利用者の対応が必要な失敗（同じ表で「しない」） | 自動では再試行しない |
| 初めての同期の合わせ方を選ぶ必要がある | 選ぶまで自動では同期しない |
| アプリの終了 | まだ送っていない変更があれば、同期してから終了する（SC-12） |
| ログインした直後・「今すぐ同期」 | すぐに同期する |

同期でこのパソコンのデータが変わったら、書籍一覧と開いている書籍の画面を読み直す（[5.3](#sc-03-書籍の表示登録編集)）。

### 8.10 すべてのデータの削除と同期

ログイン中に「すべてのデータを削除」を行う場合は、最終確認で削除する範囲を選ぶ。どちらの範囲でも、このパソコンの同期はオフ（ログアウト）にしてから消す（消した後にクラウドから取り戻さないため）。

```mermaid
flowchart TD
    start([最終確認で「すべて削除」]) --> on{ログイン中か}
    on -- いいえ --> wipe
    on -- はい --> scope{削除する範囲}
    scope -- このパソコンだけ --> out
    scope -- Google ドライブとすべてのパソコン --> s1[同期して、ほかのパソコンで<br/>足された書籍もこのパソコンに集める]
    s1 --> ok1{同期できたか}
    ok1 -- いいえ --> fail1([「何も削除していません」を表示して終了])
    ok1 -- はい --> mark[すべての書籍に<br/>削除済みの印を付ける]
    mark --> s2[同期して削除済みの印を送り、<br/>使われていない書影をすぐ消す]
    s2 --> ok2{送れたか}
    ok2 -- いいえ --> fail2([「次の同期で反映されます」を表示して終了<br/>このパソコンの書籍は削除済み])
    ok2 -- はい --> out[ログアウト]
    out --> wipe[初めての同期の前のバックアップを消し、<br/>すべてのデータを物理的に消去]
    wipe --> done([言語選択画面から始まる最初の状態])
```

| 範囲 | 結果 |
|---|---|
| このパソコンだけ（初期選択） | ログアウトしてから、このパソコンのデータを消す。Google ドライブとほかのパソコンのデータは残る |
| Google ドライブとすべてのパソコン | クラウドの書籍・ノートを削除済みにし、ほかのパソコンでも次の同期のときに削除される。その後、このパソコンのデータを消す |

- 「すべてのパソコン」で最初の同期ができない（接続できない・クラウドに読めない記録がある）ときは、何も削除しない。初めての同期にあたる場合は「統合する」で同期する。
- 時計が進んでいたパソコンで付いた未来の更新日時の書籍も確実に消えるよう、削除済みの印の日時は各書籍の更新日時より後にする。

### 9.2 取得元と問い合わせの順番

| ISBN の先頭 | 問い合わせる順番 |
|---|---|
| 978-4（日本） | 国立国会図書館サーチ → Open Library |
| 978-2・979-10（フランス語圏） | フランス国立図書館 → Open Library |
| 978-3（ドイツ語圏） | ドイツ国立図書館 → Open Library |
| 978-0・978-1（英語圏） | Open Library → 米国議会図書館 |
| それ以外（韓国・中国など） | 国立国会図書館サーチ → Open Library → 米国議会図書館 |

| 取得元 | 要求 | 使う項目 | 利用条件 |
|---|---|---|---|
| Open Library | `GET https://openlibrary.org/api/books?bibkeys=ISBN:{ISBN}&format=json&jscmd=data`（JSON） | 書籍名（＋副題）、著者、出版社 | データに新たな権利を主張しない。1秒1件まで。User-Agent でアプリ名と連絡先を名乗る |
| 米国議会図書館 | `GET https://lx2.loc.gov/sru/lcdb?…&query=bath.isbn={ISBN}&recordSchema=dc`（SRU） | 書籍名、著者、出版社 | 登録不要。利用規約の明文はない |
| フランス国立図書館 | `GET https://catalogue.bnf.fr/api/SRU?…&query=bib.isbn all "{ISBN}"&recordSchema=dublincore`（SRU） | 書籍名、著者・翻訳者、出版社 | Licence Ouverte（商用可）。出典を表示する |
| ドイツ国立図書館 | `GET https://services.dnb.de/sru/dnb?…&query=num={ISBN}&recordSchema=oai_dc`（SRU） | 書籍名、著者・翻訳者、出版社 | 登録不要・無料（データは CC0） |

- 順番は、2026-10 に6言語150冊で測った取得率に基づく。各国の本はその国の国立図書館の収録が厚く、組み合わせると 149/150 冊を取得できた。
- 以前使っていた Google Books は、API キーなしの問い合わせが共有の1日上限に達して使えず、表示上の条件（ロゴ・リンクの掲示）も満たせないため使わない。
- どの取得元でも書影は取得しない。取得結果には出典（取得元の名前）を表示する。

### 9.4 Google ログイン（OAuth 2.0）

| 項目 | 内容 |
|---|---|
| 用途 | 同期のためのログイン（Google アカウントでの許可） |
| 方式 | インストール型アプリ向けの OAuth 2.0 認可コードフロー。PKCE（`S256`）と `state` を付け、戻り先は PC 内のループバック（`http://127.0.0.1:{空いているポート}`）で待ち受ける |
| 認可 | `https://accounts.google.com/o/oauth2/v2/auth` を既定のブラウザで開く |
| トークン | 戻ってきた認可コードをアクセストークン・更新用トークンに交換する。アクセストークンは期限が来たら自動で更新し、更新後のトークンを保存し直す |
| 権限（スコープ） | `https://www.googleapis.com/auth/drive.appdata` だけ（アプリ専用領域の読み書き） |
| ログアウト | `POST https://oauth2.googleapis.com/revoke` でトークンを無効にする。通信できなくても、保存したログイン情報は消す |
| クライアント | Google Cloud に登録したデスクトップアプリ用のクライアント ID。リポジトリには含めず、ビルド時に渡す（[BUILDING.ja.md](../../BUILDING.ja.md)）。渡さずにビルドしたアプリでは同期を使えない |

### 9.5 Google ドライブ API（v3）

| 項目 | 内容 |
|---|---|
| 用途 | 同期データと書影の保存・取得 |
| 領域 | `appDataFolder`（アプリ専用領域）。ゴミ箱に入ったファイルは対象外 |
| 使う操作 | ファイルの一覧（`files.list`）、ダウンロード（`files.get`）、作成・上書き（`files.create`／`files.update`）、削除（`files.delete`）、書影の付加情報（`appProperties` の `unusedSince`）の更新、表示用のメールアドレスの取得（`about.get`） |
| ファイル | `colophon-sync.json`（同期データ、JSON）、`cover-{SHA-256}`（書影） |
| 書き換えの検出 | ファイルの ID と中身の MD5（`md5Checksum`）を比べ、ほかのパソコンによる書き換えを見つける |
| 時刻 | 応答の `Date` ヘッダーからサーバー時刻との差を測り、記録する日時の補正に使う |
| 認証 | [9.4](#94-google-ログインoauth-20) で得たアクセストークン |

## 10. 非機能要件

| 区分 | 要件 | 実現方法 |
|---|---|---|
| 移植性 | Windows / macOS / Linux で同じ機能を提供し、将来スマホにも展開できる | Flutter で1つのコードから各OS版を作る。画面は幅に応じて配置を変える |
| 多言語 | 7言語に対応し、言語を後から増やせる | 文言を言語ごとのファイルに分離。データには言語に依存しないコードを保存 |
| オフライン | ISBN 取得と同期以外はネットワークなしで動く。同期できない間も、操作はそのまま続けられる | データは端末内の SQLite に保存。同期は毎回すべての内容を突き合わせるので、送れなかった変更は次に同期できたときに送られる（一時的な失敗は自動で再試行し、起動時にも同期する） |
| データ保全 | 保存・インポートの途中で失敗してもデータが壊れない | トランザクションで一括反映。失敗時は元に戻す |
| データ保全 | 同期の途中で失敗・中断しても、どのパソコンのデータも壊れたり失われたりしない | このパソコンへの書き込みは最後に1つのトランザクションで行う。送る前と送った直後にクラウドの書き換えを確かめ、ほかのパソコンの変更を上書きしない。書影は同期データより先に送る。クラウドに読めない記録があれば送らない。初めての同期の前にバックアップを保存する（[8.7](#87-同期)・[8.8](#88-初めての同期)） |
| データ保全 | 複数のパソコンで編集しても、どのパソコンでも同じ結果に落ち着く | 書籍・ノートごとに更新日時の新しい方を採用し、同時刻なら削除、さらにクラウド側を採る。パソコンの時計のずれは Google のサーバー時刻との差で補正する（[8.7](#87-同期)） |
| データ保全 | アプリの更新でデータ構造が変わっても既存データを使い続けられる | スキーマのバージョン管理と自動移行。新しい版で作られたデータは開かずに案内する。同期データも形式の版を持ち、新しい版のものは読まず上書きもしない |
| データの持ち出し | 利用者がいつでも自分のデータを取り出せる | 3形式のエクスポート。JSON は公開された簡単な構造 |
| 応答性 | 重い処理で画面が固まらない | 画像処理・ZIP 作成は別処理（Isolate）。処理中は表示を出す |
| プライバシー | 利用者のデータを、利用者が選んだ先以外に送らない | 通信は、ISBN 取得時の ISBN の送信と、同期を使う（ログインした）場合の利用者自身の Google ドライブとの送受信だけ。同期は `drive.appdata` の権限でアプリ専用領域だけを使い、利用者のほかのファイルは読まない。設定は送らない。ログアウトすると Google 側のトークンも無効にする |
| セキュリティ | ログイン情報を漏らさない | ログイン情報は OS の安全な保管場所に保存する。ログインは PKCE と `state` を使い、ブラウザからの戻り先は PC 内（127.0.0.1）だけで待ち受ける。Google のクライアント ID はリポジトリに含めない |
| 誤操作防止 | 取り返しのつかない操作の前に確認する | 削除・全置き換え・未保存の破棄・ログアウトで確認ダイアログ。すべてのデータの削除は二段階で確認し、ログイン中は削除する範囲も選ぶ。初めての同期の合わせ方は利用者が選ぶ |
| 配布・削除 | 各 OS の一般的な形式で配布し、利用者がデータを確実に消せる | Windows はインストーラー（アンインストール時にデータを消すか確認）、macOS は .dmg、Linux は Flatpak（データも消せる）と .deb。アンインストーラーでデータを消せない形式のため、アプリ内に「すべてのデータを削除」を用意する（[BUILDING.ja.md](../../BUILDING.ja.md)） |
| 見分けやすさ | アイコンだけで「本の管理とノートのアプリ」と分かり、3つの OS のどれでも浮かない | 並んだ3冊の本の背（深緑・紺・えんじに金の帯）と、上に飛び出したオレンジの付箋を、淡い水色の角丸四角の台座に載せる。台座の形と余白は macOS の標準に合わせ、Windows と Linux の小さいサイズは余白を詰める。40px 以下では帯と棚を省く |
| アクセシビリティ | 色覚の違いや好みにかかわらず読みやすい | 6種類の配色テーマと明るさの設定。全テーマでコントラスト比 4.5:1 以上。ステータスはアイコン＋文字でも区別。ユニバーサルテーマは色覚シミュレーションで検証（[5.4](#54-配色テーマ)） |

## 11. 制約・既知の制限

| 内容 | 影響 |
|---|---|
| 書籍名順の並びは文字コード順 | 日本語は読み（五十音）順にならない。アクセント付きの文字は英字の後ろに並ぶ |
| HEIC 形式の画像は読み込めない | iPhone で撮った写真は JPEG などに変換してから設定する |
| 翻訳者・監修の判別は取得元の表記に依存 | 取得後に利用者が確認・修正する |
| 同じデータベースを複数のアプリで同時に開く想定はない | 書き込みが重なると最大3秒待ち、それでも競合すれば保存エラーになる |
| 各OS版はそのOS上でしかビルドできない | [BUILDING.ja.md](../../BUILDING.ja.md) 参照 |
| 同期は Google ドライブだけに対応し、Google アカウントが必要 | ほかのクラウドサービスでは同期できない |
| Google のクライアント設定なしでビルドしたアプリでは同期を使えない | 設定画面の同期欄に「使えません」と表示される（[BUILDING.ja.md](../../BUILDING.ja.md)） |
| 同じ書籍を2台で変えると、更新日時が新しい方の書籍が丸ごと採用される | 項目ごとには合わせないので、古い方で変えた項目は失われる（ノートは1件ずつ判定する） |
| 設定は同期しない | 表示言語・配色テーマなどはパソコンごとに設定する |
| 使われなくなった書影は、しばらく Google ドライブに残る | 7日以上たってから消す（すべてのデータの削除で「すべてのパソコン」を選んだ場合はすぐ消す） |
| 同期で届いた変更を自動で読み直すのは、書籍一覧と開いている書籍の画面だけ | 開いている検索画面・タグ管理画面には、開き直すまで反映されない |
